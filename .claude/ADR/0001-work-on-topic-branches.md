# ADR 0001: 作業用ブランチで変更とコミットを行う

- 日付: 2026-10-26
- 状態: 採用
- 適用範囲: sandbox-notion-clone のみ

## 背景

このリポジトリは学習用であり、一つの作業を順番に進める運用を基本とする。
従来の AGENTS.md は worktree の配置場所と後片付けだけを規定しており、
作業用ブランチの作成や main への直接コミット禁止は明記していなかった。
変更を作業単位で整理できるよう、通常の手順を統一する。

## 決定

変更作業を始める前に作業用ブランチを作成し、そのブランチ上でコミットする。
main への直接コミットは禁止する。同じ作業のブランチがある場合は再利用し、
コミットごとには新しいブランチを作成しない。

通常は同じ作業ディレクトリでブランチを作成し、worktree は必須にしない。
並行作業などのために worktree を利用する場合は、AGENTS.md の配置ルールに従う。
すでに main 上で変更していた場合も、その変更を保持して作業用ブランチへ移してからコミットする。

コミットだけを依頼された場合はローカルコミットまでで終了する。
そのためのリポジトリ専用スキルを local-commit とし、push・PR 作成まで進める
quick-pr と用途を分ける。

## 検討した選択肢

| 選択肢 | 評価 |
| --- | --- |
| 作業用ブランチを必須にする | 作業単位で履歴を分けられ、同じディレクトリで学習を続けられるため採用 |
| 作業ごとに worktree とブランチを作成する | 並行作業には便利だが、依存関係や環境の準備、後片付けが増えるため標準手順にはしない |
| main に直接コミットする | 作業単位の分離を保証できないため採用しない |

## 結果

ブランチの作成とコミット前の確認が必要になる一方、worktree の管理負担を増やさずに
作業単位の履歴を残せる。並行作業時のファイル分離は自動では得られないため、必要な場合に
worktree を選択する。この決定は他のリポジトリの運用を変更しない。
