# ADR 0003: 公開 TIL は質問の原文ではなく理解を整理して記録する

- 日付: 2026-10-26
- 状態: 置換済み（[ADR 0004](0004-preserve-author-voice-in-til.md)）
- 適用範囲: sandbox-notion-clone の公開 TIL

## 背景

このリポジトリを、他の人にも学習の内容や経緯が伝わる記録として残したい。
一方、質問時の率直な言葉や AI との会話をそのまま掲載すると、理解した内容よりも
質問時点の理解不足に注目されることが気になる。また、長い回答の転載は復習しづらい。
2026-10-26 の TIL にある疑問を整理する方法として、今後参照できる記述方針を残す。

## 決定

公開 TIL は会話の逐語録ではなく、その日に得た理解を自分の言葉で整理する記録とする。

- 疑問を整理する見出しは「確認したこと・理解の整理」を基本とする。
- 「私の疑問／AI の回答」という区分よりも、技術的なテーマごとにまとめる。
- 基本構成は「要点 → 短いコード例 → 注意点」とし、必要に応じて比較表や
  「次に確認すること」を追加する。小さなテーマにすべての項目を強制しない。
- 質問の原文は「何を確認し、何を区別できるようになったか」が分かる表現にする。
  例: 「! で undefined を防げる？」は「型のアサーションと非同期処理の制御の違いを確認」とする。
- 難しい用語で取り繕わず、自分が説明できる範囲を正確に記載する。
  未確認の内容や残る疑問は、理解済みとせず明示する。
- AI の回答は丸ごと転載せず、理解した要点を選び、必要なら根拠へのリンクを添える。
- 率直な質問メモを残したい場合は、公開 TIL と分けて個人用の非公開メモに保存してよい。

## 代替案

- 質問と AI の回答を原文のまま公開する: 会話の経緯は残るが、長くなりやすく、
  公開時の懸念と復習のしづらさがあるため標準形式にはしない。
- 疑問を省き、結論だけを記録する: 短くなるが、誤解しやすい点や確認の背景が失われる。
  注意点や未解決事項も必要に応じて残す。
- 学習メモをすべて非公開にする: 率直に記録できるが、学習履歴を公開する目的を満たせない。

## 結果

質問時点の表現に依存せず、得られた理解と次の課題が伝わる学習履歴にできる。
復習しやすくなる一方、公開前に内容を選び、説明を確認する作業が必要になる。

この ADR の追加だけでは既存 TIL の本文を書き換えない。
すでにコミットした原文は、本文を更新しても過去の Git 履歴には残る。
履歴の書き換えはこの方針の対象外とする。

ADR 0002 の保存方針に従い、この ADR 自体は `.claude/ADR/` のローカル記録とする。
TIL の公開方針とは別に、ADR の Git 追跡設定は変更しない。
