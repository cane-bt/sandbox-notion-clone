# ADR 0013: 機能・開発設定・学習記録を別 PR に分ける

- 日付: 2026-11-01
- 状態: 採用
- 適用範囲: sandbox-notion-clone

## 背景

同日に実施した学習とアプリ修正を一つにするか、受講番号ごとに分けるか検討した。受講日と実装の責務は一致するとは限らない。

## 決定

- PR は認証実装、ESLint と未使用 import、学習記録の3つに分ける。横断的な ADR 公開は独立 PR にする。
- 認証のコミットは API、フォーム接続、共有ユーザーと遷移という動作単位で分ける。文書の要件修正は追加コミットにする。
- TIL は運用・テンプレートの変更と、原本・復習版・データ・保存記録の一式を分ける。一式の整合性を壊す細分化はしない。
- main に直接コミットせず、既存 PR は同じブランチへ追加コミットして push する。履歴を強制書き換えしない。
- 関連する README・英日 CHANGELOG を更新し、検証の成功・既存の失敗・未実行を区別して報告する。
- 既存の未コミット作業を保持するため、必要時は .claude/worktrees/ の worktree で分離する。
- コミットのみ、PR 作成、マージの依頼範囲を区別する。今回はユーザーの明示依頼により各 PR を main へマージする。

## 代替案

日単位の単一 PR は責務が混在する。教材の動画ごとの PR は一体の機能を分断しやすい。PR を増やしすぎず、コミットで実装手順を追える構成を採用する。

## 結果

独立レビューがしやすい一方、共有ドキュメントはマージ時に統合が必要になる。受講記録はコードのコミット数から推測しない。既存 PR は #8・#9・#10。
