# ADR 0019: token の保存・送信と起動時のユーザー復元

- 日付: 2026-11-02
- 状態: 採用
- 更新対象: ADR 0011 の token 保存・起動時復元に関する未実装の記録

## 背景

講座22〜24に対応する変更を、token 保存、認証付き取得 API、起動時復元の順で学習・レビューしたい。

## 決定

- 登録・ログインで返る token を localStorage の token キーへ保存し、保存成功後に共有ユーザーを更新する。
- 共通 Axios の request interceptor で、保存済み token がある場合に Authorization: Bearer を付与する。認証 endpoint を含む同クライアントの全通信が対象。
- authRepository.getCurrentUser は GET /auth/me の本文を User に変換する。受け側 API は別バックエンドの責務。
- App の Effect で起動時にユーザーを取得し、完了まで読み込み表示にする。取得失敗時は共有ユーザーを未設定にする。
- Effect 内に取得関数を定義し、依存配列に setCurrentUser を含める。cleanup 後は古い結果を反映しない。通信自体のキャンセルや重複排除は実装しない。
- React StrictMode は維持する。開発時にリクエストが追加実行され得る。

## 代替案

HttpOnly Cookie による保存はブラウザーの JavaScript から token を読む設計とは異なり、バックエンドとの調整が必要。今回は教材に沿って localStorage を使う。データ取得ライブラリや専用 Hook の導入は保留する。

## 結果

再読み込み時にバックエンドから共有ユーザーを復元する処理を持つ。localStorage は JavaScript から参照可能であり、XSS 対策やサーバーの認証・認可は引き続き必要。token 更新・ログアウト時の破棄・エラー種別ごとの表示は未対応。実バックエンドとの通信は未検証であり、永続セッションが本番仕様として完成したとは扱わない。
