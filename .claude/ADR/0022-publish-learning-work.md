# ADR 0022: 学習作業の公開と元ディレクトリの整理を専用スキルで扱う

- 日付: 2026-11-05
- 状態: 採用
- 適用範囲: sandbox-notion-clone

## 背景

学習に伴う実装・設定・TIL・ADR を別 PR に公開した後、元ディレクトリに未コミット差分が残り、公開状況と作業の継続先が判別しにくくなった。既存の `quick-pr` も複数 PR を扱うが、学習全体の対象選定と元ディレクトリの整理までを明確な用途として分ける必要がある。

## 決定

- リポジトリ専用の `publish-learning-work` を新設する。今回の学習作業を日付だけで限定せず、適切な PR とコミットへ整理して公開し、元ディレクトリの整理と継続先の案内まで扱う。
- 個別作業の公開は `quick-pr`、ローカルコミットのみは `local-commit` を維持する。新スキルから `quick-pr` を反復実行せず、グローバル版は変更しない。
- 元ディレクトリの状態記録、公開コミットとの照合、対象外・追加編集の保持、整理未完了の報告を `AGENTS.md` の共通完了条件に置き、既存のリポジトリ版 `quick-pr` にも適用する。
- 全体が clean であることは要求しない。公開済みの重複だけを復元可能な状態で整理し、保持した差分と継続先を明示する。安全に分離できない場合は公開状況と整理未完了を区別する。
- スキルの編集依頼を公開操作の許可と解釈しない。マージは別途明示依頼に従う。ADR 0014 のスキル・個人設定のローカル管理を維持する。
- 初期実装は指示文で構成し、専用スクリプトは導入しない。実運用で反復処理や失敗が確認された場合に必要な範囲で検討する。

## 代替案

- 現状維持: 元ディレクトリの差分残存と報告の曖昧さを解消しない。
- `quick-pr` と共通ルールのみの最小修正: 整理の問題には対応できるが、学習全体の対象選定と個別作業の公開を区別しにくい。
- グローバルの `quick-pr` を変更: 他リポジトリにも固有の学習運用を持ち込むため採用しない。

## 結果

公開依頼の入口と完了条件が明確になる一方、二つの公開スキルの整合を維持する必要がある。整理条件は共通ルールへ集約する。ADR 0001 の同一ディレクトリ中心の運用、ADR 0013 の責務による PR 分割を維持し、その完了条件を補足する。

採用・指示文の実装と、実際の公開操作の検証は区別する。実運用の確認対象は、部分的な stage、formatter による差異、公開途中の失敗、並行編集がある場合の変更とステージ状態の保持とする。
