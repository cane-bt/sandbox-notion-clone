# ADR 0027: Open PR の順次マージを専用スキルで扱う

- 日付: 2026-11-20
- 状態: 一部置換（lint の許容条件のみ [ADR 0028](0028-allow-learning-lint-findings.md) で更新。その他は維持）
- 関連: [ADR 0022](0022-publish-learning-work.md) の公開処理との役割分担を補足する。公開時にマージしない方針は維持。

## 背景

学習作業を複数 PR に分けて公開した後、依存関係に合う順序で `main` に取り込むための専用スキルが必要になった。設計レビューで対象固定、最新状態の確認、停止範囲、再開時の照合を整理し、ユーザーが作成を依頼した。

## 決定

- リポジトリ専用の `merge-open-prs` を設ける。通常の明示呼び出しは対象選定からマージ完了確認までを含む。「順序だけ」、スキルの作成・編集・評価はマージ許可にしない。
- 指定なしなら開始時点の Open・非 draft・`main` 宛てを対象に固定する。依存先を先に処理し、1件の完了後に残りを再評価する。途中追加・別 base の PR を自動で含めない。
- head と base の SHA に検証を対応付け、head を拘束してマージする。必須条件を迂回せず、非必須の既存失敗も証拠と許容方針なしに免除しない。
- 競合・失敗のある PR とその依存先を保留し、独立性を確認できる PR は続行できる。全体の取得失敗・マージ結果不明・予約未完了では後続を止める。
- マージ方式は明示指定、文書化された方針、唯一許可された方式の順で選ぶ。決まらない場合だけ確認する。
- 待機は既定で1 PR あたり10分を上限とする。予約とマージ完了を区別し、予約が残る場合は報告する。期限切れを取消しとみなさない。
- 初版は `SKILL.md` と確認ケースの2文書。専用 runner・状態保存ファイルは導入しない。再開時は会話内の前回対象と実状態を照合する。
- 競合修正・push・ブランチ削除・ローカル `main` 更新・既存差分の整理を暗黙に含めない。作成依頼だけをコミット・公開・マージの許可にしない。
- 作成後のユーザーの明示依頼により、`merge-open-prs` の本文と確認ケースを公開対象にする。ADR 0014 のローカル管理方針をこの2ファイルに限って変更し、他のスキル・個人設定は変更しない。

## 代替案

- 毎回個別に依頼する: 新規スキルは不要だが、順序・停止・再開の判断を繰り返す。
- `publish-learning-work` に統合する: 公開とマージの依頼範囲が混在するため採用しない。
- 専用 runner を作る: 状態照合を機械化できるが、初版の運用実績がなく保守範囲が増えるため見送る。

## 結果

公開は既存スキル、取り込みは新スキルと分担する。指示文と確認ケースを作成し、形式・リンク・机上の判断を検証する。ローカルの `gh pr merge --help` で `--match-head-commit` の存在を確認した。実際の保護設定・queue・許可方式の取得と GitHub 上のマージ動作は未検証で、実行時に確認する。
