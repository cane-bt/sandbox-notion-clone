# 学習中は BlockNote の遅延読み込みを見送る

2026-11-23　今回の実装は見送り。将来の採用は未決定。

## 背景

[PR #50](https://github.com/cane-bt/sandbox-notion-clone/pull/50) では、`App` から `NoteDetail`、`Editor`、BlockNote までが静的な `import` でつながる。サインインやホームでもエディターのコードが初期 JavaScript に含まれ、ビルドは成功するが、Vite の既定値である 500 kB を超えるチャンクの警告が出る。

同じインストール済み依存を使い、一時コピーで本番ビルドを比較した。値は minify 後、gzip 前のサイズ。

| 条件 | 初期 JavaScript | 別途取得するエディターのチャンク |
| --- | ---: | ---: |
| PR #50 の変更前 | 393.29 kB | — |
| BlockNote 導入後 | 1,404.51 kB | — |
| `Editor` の遅延読み込みを試した場合 | 395.19 kB | 1,008.97 kB |

分割すると初期 JavaScript は導入前に近づく。エディター側は引き続き警告の対象となる。ブラウザーで本文を編集できるまでの時間は未計測。

## 決定

今回は教材に沿った学習を優先し、静的な読み込みを維持する。チャンク警告は現段階では許容する。

## 代替案

- 本文だけを遅延読み込みする。[ノート詳細](../../src/pages/NoteDetail.tsx) で `React.lazy` を使い、名前付き export の [Editor](../../src/components/Editor.tsx) を読み込む。`Suspense` で待機中の表示を、本文だけを囲う Error Boundary で失敗時の案内を出す。[TitleInput](../../src/components/TitleInput.tsx) は境界の外に置き、既存の保存と再試行を使えるようにする。
- 失敗時は手動での再読み込みを案内する。タイトルを編集した場合はフォーカスを外し、「保存中...」が消えて保存エラーが出ていないことを確認してから再読み込みする。自動再読み込みはフォーカスが外れた直後の非同期保存と競合し得る。[ADR 0030](0030-save-note-title-on-blur.md)
- 詳細 API とエディターの取得を並列化する方法もある。本文だけを遅延読み込みする案では、初回はノート取得成功後にチャンクの取得が始まる。並列化すれば待ち時間を重ねられるが、存在しないノートでもチャンクを取得し得る。

## 結果と再検討条件

現在はサインインやホームでも初期チャンクの転送負担が残る。最適化を再検討する際は、まず本文だけを分割し、本番ビルドで次を確認する。

1. ホームではエディター用チャンクを取得しない。
2. チャンク取得を失敗させてもタイトルを編集でき、保存と失敗時の再試行が機能する。
3. キャッシュを無効にしてノートを直接開き、本文が編集可能になるまでの時間を現状と比較する。詳細 API の完了待ちが編集開始を遅らせると確認できた場合に、並列取得を比較する。
