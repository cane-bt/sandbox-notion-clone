# TIL の整文と復習版の作成

sandbox-notion-clone 内の TIL にのみ適用する。
本人の言葉と学習の過程を残し、AI の補足を区別して復習できる記録を作る。
このスキルは、改善版 til-review-v2 の方式を採用した正式版。

## 入力を確認する

`$til-review _TIL/YYYY-MM-DD.md` のように対象パスだけの指定でも、
元メモと、このセッションで参照できる実行当日の関連する会話を確認して生成する。

- リポジトリのルール、対象ファイル、対応する既存の復習版を読む。
  未コミットのメモや追記も入力として扱う。
  日付名の入力が本人の原本か生成済みの完成版か、本文・会話・Git 履歴から確認する。対応する `_draft/` の原本があれば併せて読む。判断できなければ退避・上書きの前に確認する。削除済みの原本・旧版を再生成しない。
- 指定された復習版がある場合はそれを優先する。指定がなければ、同じ原本に対応する
  日付名の完成版を優先し、それがない場合だけ `-review.md` と `-review-vN.md` の最大版番号を引き継ぎ候補にする。
  版番号は優劣や正しさの保証ではなく、比較対象を選ぶために使う。
- 復習版が入力なら、その中の元ファイルへのリンク等から原本を確認する。
  原本が特定できない場合は指定ファイルを基に進め、参照範囲を報告する。
- 実装に関する説明は必要なコードで確認する。TIL 整理のためにアプリのコードは変更しない。

## 入力用の作成メモ

本人が日々書く原本の推奨形式は [\_TIL/_TEMPLATE.md](../../../_TIL/_TEMPLATE.md)。
この形式は任意であり、既存の自由形式のメモも受け付ける。
入力テンプレートの作成や説明を求められたときに参照する。復習版の生成には下記の出力用テンプレートを使う。

- 「自分の言葉でまとめたこと」「自分で試したこと」「次に自分で確認したいこと」は本人の記述として扱う。
- 「確認したいこと」は確認の出発点、「教材・参考資料の内容」「AI から得た説明」は明示された出所に従って扱う。
- 未記入の欄や入力用の説明コメントは学習内容として転載しない。欄を埋めるために本人の理解や実施結果を補わない。

## Udemy の受講進捗を残す

復習版の「参考資料」の後、「元の学習メモ」の直前に「Udemy の学習進捗」を置く。
当日の成果と対象日までの累積進捗、受講日の降順の履歴をまとめ、学習の継続を振り返れるようにする。

- [README](../../../README.md) の講座名・URL・総動画数・確認日を読む。講座ごとに集計し、URL の講座部分で同一講座を識別する。
  総数の根拠は README の記録とし、Web 上で確認したとは扱わない。総数が不明・無効なら割合は未確認とする。
- 対象日までの `_TIL/` の日付名の完成版から、各日の受講記録だけを読む。
  当日の会話による明示申告も利用する。生成済みの累積値・履歴表は入力として再集計せず、各日の記録とその出所を照合する。
  同じ日・講座の記録を統合し、版の数で受講回数を増やさない。原本にない追記も保持し、訂正は根拠付きで反映、解消できない矛盾は未確認とする。
- 当日の記録には受講日、講座、動画番号・範囲、完了／途中／復習・再視聴、出所を残す。
  番号が連続すると確認できる場合だけ範囲にまとめる。「18、20」を「18〜20」にしない。
  レクチャーに動画以外が混ざる場合は動画と対応できる番号だけを動画数に数え、対応が不明なら割合を断定しない。
- 本人の明示した実績を根拠とし、コード・コミットとの対応、AI の分析、質問中の番号から受講や完了を推測しない。
  教材一覧の累積完了表示を当日の受講実績にしない。有用な実装との対応は AI の参考情報として分ける。
- 日付付き TIL の「Udemy の受講進捗」に本人が記載した完了記録は、別の受講日や累積記録である旨の明示がない限り、TIL の対象日の完了申告として扱う。
  受講日欄の空欄や教材表示の貼り付け形式だけを理由に再質問しない。明示された受講日を優先し、既存記録・本人の説明との解消できない矛盾がある場合だけ確認する。
- 対象日までに完了したと確認できる動画番号の集合を数え、重複・再視聴を加算しない。途中は完了数に含めない。
  受講日不明でも対象日以前の完了と確認できれば累積に含められるが、受講日を捏造しない。
  後日初めて確認した完了を過去へ遡及させない。時点不明の完了は「累積への算入保留」として別枠に残す。
- 累積完了数／総動画数と割合（小数第1位）、当日に新しく完了した本数、復習した本数を確認できる範囲で示す。
  記録不足なら「確認できた完了数」と明記する。記録が一切なければ完了数・割合は未確認とし、0%や未受講と断定しない。
  過去との比較ができない場合は当日の新規完了数も未確認とする。総数を超えるなど整合しない場合は丸めず確認事項にする。
- 当日の記録の後に、受講日・講座・当日の内容・その日までの累積・出所リンクの履歴表を新しい日付順に置く。
  受講日不明の記録は表の下の別枠にする。受講実績のない日付を作らず、メモはあるが範囲不明の日は「受講範囲未確認」と表示できる。
  各行の累積もその日以前の根拠だけで計算し、不明なら未確認とする。履歴が長くてもこの節は「元の学習メモ」の直前に置く。
- 上記の日付の扱いでも情報が不足する場合は、不足箇所だけを未確認として生成を続ける。受講記録自体がなければ「対象日の受講範囲：未確認（情報なし）」とする。
  本人が明示した場合だけ「受講なし」とする。次に取り組む候補は途中の記録等に基づく AI の提案とし、不明な未受講番号を作らない。
- 出力に学習対象日・整理日・集計に使用した総数とその確認日を残す。README の総数が変わっても保存済みの復習版は更新しない。
  過去日を再生成する際は当時の総数を既存版等で確認し、現在の総数しかなければ現在の基準による再計算と明記する。
  スキル更新だけでは過去の TIL を書き換えない。完了報告では進捗の確認結果と不足情報を伝える。

## 当日の会話を選ぶ

当日は利用可能な日時情報とユーザーのタイムゾーンを基準にする。
日付が異なる TIL を指定された場合も、当日の会話のうちその TIL に関係する内容だけを加える。
学習対象日と整理日を区別し、過去の会話を当日の学習として扱わない。
メッセージの日付が不明な場合は推測せず、「参照可能な現セッション（日付の区切り未確認）」等と記す。

- 生成前に、関連する疑問・回答・後からの訂正・コード例・未解決事項をテーマ単位で洗い出す。
  各テーマを既存の節へ統合するか、追加テーマにするか判断する。この作業用一覧を別ファイルにする必要はない。
- 長いセッションの後半に出たテーマも確認する。同じ説明の繰り返しは統合し、
  後から訂正された場合は妥当性を確認して訂正後の説明を採用する。
- 雑談、AI の作業進捗報告、操作履歴は除く。本人の受講進捗は上記の節に残す。
  スキル・ADR の話題は、対象 TIL の学習に関係するときだけ含める。
- 別セッションや、現在参照できない会話を読めるものとして扱わない。
  会話が参照できなくても、元メモと利用可能な資料で生成を進める。
  不足が結論に影響する箇所は未確認とし、完了報告で会話の反映範囲を伝える。

## 対象ファイル・疑問・解説を対応付ける

- 今後作成・更新する復習版では、目次の後に「疑問と解説の一覧」を置く。対象ファイル・関数等、本人の疑問の要約、説明した要点と本文へのリンクをテーマごとに対応付ける。
- 本文の各質問テーマにも「対象ファイル・箇所」を明記し、「確認の出発点」と「AI による補足」で疑問と回答を対応させる。追加テーマでも同じ形式を使う。回答がなければ「未回答」、一部が残れば未解決の内容を明示し、説明したことを本人の理解済み・動作確認済みとしない。
- 対象はリポジトリ相対パスを表示し、TIL からの相対リンクを付ける。関数・コンポーネント名や文書の節名も添える。複数ファイルの関係についての質問では双方を記録する。
- 行番号は質問時点で確認できた場合だけ「質問時点の行番号」として添える。後の編集でずれるため行番号だけを手掛かりにしない。元の質問が TIL 内の例を対象とする場合は、その TIL と節を示し、実装ファイルの質問に置き換えない。
- 対象が分からなければ「対象ファイル未確認」、一般的な質問なら「特定ファイルなし」とする。質問・説明の日時や対象を推測しない。繰り返しの質問は統合できるが、追加の疑問や説明の訂正は分かる形で残す。
- このルールの導入だけでは過去の TIL や本人原本を一括変更しない。

## 出所を区別して整理する

元ファイル全体を「本人の文章」とみなさず、内容を次のように扱う。

| 入力の種類                 | 出力での扱い                                     |
| -------------------------- | ------------------------------------------------ |
| 本人の要約・具体例・着眼点 | 「元の学習メモ」に原文を基本として保持           |
| 本人の質問                 | 「確認の出発点」に中立的に整理                   |
| 教材の引用                 | 教材由来と明示し、必要な短い抜粋や要約を使用     |
| AI の回答                  | 「AI による補足」に配置                          |
| 出所が判別できない文章     | 本人や AI と断定せず、出所未確認の記述として保持 |

本人の文章の編集は見出し階層・改行・明白な誤字と、文言・意味を変えないコード表記の装飾などにとどめる。
例えば「取り回ししやすくなる」を「保守性向上」に全面的に置き換えない。
技術的な不正確さは黙って直さず、対応する補足で元の記述と訂正理由を示す。

会話中に本人が説明した理解も、実際の発言に基づき「セッション中の本人の整理」として残せる。
相づちだけから理解を推測しない。AI の説明を本人の理解・要約として書かない。
質問時点の自己評価を繰り返さず、何を確認したかったかを残す。

## 既存の復習版を引き継ぐ

原本・引き継ぎ候補の復習版・新しい会話を照合する。
復習版に後から加わった注意書きや説明、修正を、原本にないという理由で落とさない。
ただし、追記の著者を推測せず、既存の AI 説明は引き続き AI の補足として扱う。

新しい訂正と古い説明が矛盾する場合は根拠を確認する。
解消できなければ断定せず、確認事項として残す。
古い説明の機械的な継承や、同じ内容の重複追加を避ける。

## 学習時点と確認時点を区別する

- 過去の会話を現在の実装状況として転載しない。実装や設定への言及は確認時点を示す。
  例: 「2026-10-26 の確認時点では、初期化チェックは有効になっていない」。
- 後日確認した現在のコードを、過去の状態の証拠として使わない。
- 「次に確認する候補」は最新の関連コード・会話と照合し、完了済みと確認できるものを除く。
  一部だけ実装された場合は残る作業を示す。コードの存在だけで動作確認済みとしない。
- 実装済みのコード、説明用の例、未確認の仕様、AI の提案を区別する。
  技術情報の確認が必要なら公式資料を参照し、役立つリンクを添える。

## テンプレートから生成する

必ず [assets/til-review-template.md](assets/til-review-template.md) を読み、構成の土台にする。

- テーマの節を必要な数だけ繰り返し、内容のない節は省略する。
- すべてのテーマに背景・コード・注意点・参考リンクを要求しない。復習に必要な量に絞る。
- 同じ補足は一か所にまとめ、別の節から必要なら参照する。
- 骨組みを埋めるために学習内容を作らない。AI の追加提案は本人の決定にしない。
- プレースホルダーと編集用コメントを完成版に残さない。ただし TOC 更新用の `<!-- TOC:START -->` と `<!-- TOC:END -->` は保持する。

### 「元の学習メモ」を最終節にする

- 完成版は「学習本文・確認事項 → 参考資料 → Udemy の学習進捗 → 元の学習メモ」の順にする。「元の学習メモ」はその配下の補足・出所未確認の記述も含めて最後に置き、その後へ別の節や追記を追加しない。内容のない節を省略しても、元メモがある場合は必ず最終節にする。
- 初回生成と再レビューの両方に適用する。既存版の冒頭にある場合は本文を保持して移動し、目次を再生成する。退避済み原本のバイトは変えず、対象外の過去 TIL は一括移動しない。

## コード表記を整える

[リポジトリの AGENTS.md](../../../AGENTS.md) の「ドキュメント内のコード表記」に従う。
完成版では本人の文章にも、文言・意味・出所を変えない Markdown 装飾を追加できる。
退避済み原本には適用しない。既存の説明やコード例を装飾のために増やさない。

## 集計して日付名へ保存する

- 完成版は `_TIL/YYYY-MM-DD(曜日).md` とし、同日の更新はそのファイルへ反映する。版の履歴は Git で管理する。未コミットの追記も引き継ぐ。
- 初回の本人原本は `_TIL/_draft/` の同名ファイルへ全バイト保持して退避し、元の日付名へ完成版を保存する。元の内容を読み取ってから保存までに変更がないか再確認する。退避先は新規作成し、既存ファイルを上書きしない。退避後のバイト一致を確認してから完成版を保存する。
- 退避先が既に存在する場合は初回保存を繰り返さず、原本と完成版の内容を確認する。再レビューでは退避済み原本と完成版と本人の追記を照合し、完成版のみ更新する。完成版を原本へ上書き・退避しない。
- 原本を削除済みの日は、完成版と本人の追記だけで確認できる範囲を明示して更新する。完成版から原本を捏造・復元しない。11月1日の削除済みファイルも復元しない。
- 本人の文章は完成版内で AI の補足と分離して保持する。退避原本内の相対リンクは移動で基準が変わるため影響を説明し、原本のバイトを変えて修復しない。完成版には存在する退避原本へのリンクを付ける。
- 日付名の完成版にある当日の受講実績と出所、本人申告から重複を除いて集計する。累積表や旧版を足し合わせない。
- `_data/`、`.review-state/`、新たな `review-vN` は生成しない。旧 `workflow.py` と `references/workflow.md` の保存・再開手順は使用しない。
- `scripts/update_toc.py` で完成版の目次を更新し、`--check` で確認する。削除・改名した参照先へのリンクも修正する。
- 提示のみならファイルを変更しない。コミット・公開は別途ユーザーの依頼範囲に従う。

## 生成結果を照合する

- 原文の本人の要約・具体例・着眼点と生成結果を実際に比較し、欠落や過度な言い換えがないか確認する。
  見出し・改行・明白な誤字・コード表記の装飾以外の変更は必要性を見直し、技術訂正を原文の置換にしない。
- 洗い出した関連テーマを照合し、重要な後半の話題や訂正が抜けていないか確認する。
- 疑問と解説の一覧から本文へ移動でき、対象ファイル・箇所、疑問、解説内容・未回答事項の対応が一致するか確認する。
  入力に含まれる通常のファイル質問、複数ファイルの関係、一般論・対象不明、未回答、AI の自発的な補足について、それぞれ対象と出所を混同していないか照合する。検証のために存在しない質問を追加しない。
- 既存版の追記・修正が失われていないか、出所・時点・未確認事項の扱いが正しいか確認する。
- 「元の学習メモ」が最終節で、その後に別の節・追記がないこと、Udemy の学習進捗が参考資料の後かつ元メモの前にあることを確認する。当日の記録・累積・降順の履歴・出所も入力と照合する。
  欠けた番号や当日の完了状況を推測で補っていないかも確認する。
- Markdown の見出し・表・コードブロック・相対リンクを確認する。本文・表・見出しのコード表記の漏れと過剰な装飾を確認し、装飾によって本人の文言・コード・リンク先が変わっていないことを照合する。
- 元ファイルと既存版の内容を作業前後で比較し、本人の文章が完成版内に保持され、対象外の旧版を変更していないことを確認する。

完了時は出力先、反映した主要テーマ、引き継いだ版、受講進捗の確認結果と不足情報、会話の参照範囲に不足があればその範囲を簡潔に報告する。
