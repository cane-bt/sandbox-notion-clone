# 2026-10-25 の学び

## React Routerによる画面の切り替え

React Routerは、URLと表示する画面の対応関係を定義するためのライブラリです。今回のコードでは、`react-router-dom`から必要なコンポーネントを読み込んでいます。

### `Route`の`path`と`element`

`Route`では、`path`でURLの条件を、`element`で表示するReact要素を指定します。
次のコードは、「`/signin`にアクセスしたら`Signin`を表示する」という意味です。

```tsx
<Route path="/signin" element={<Signin />} />
```

### ルートの親子関係で、画面の共通部分を表現する

複数の画面で共通部分を使う場合は、共通の枠を親ルートに、切り替わる内容を子ルートに配置します。画面全体をそれぞれ定義する代わりに、共通の構造と個別の内容を組み合わせて表示できます。

```tsx
<Routes>
  <Route path="/signin" element={<Signin />} />
  <Route path="/signup" element={<Signup />} />

  <Route path="/" element={<Layout />}>
    <Route index element={<Home />} />
    <Route path="notes/:id" element={<NoteDetail />} />
  </Route>
</Routes>
```

親コンポーネント内の`Outlet`が、子ルートの画面を表示する場所になります。また、`index`は、親と同じURLにアクセスしたときに表示する標準の子画面を指定します。

### 相対パスは、親との関係を基準にした指定

絶対パスは、URLのルートを基準にした指定です。相対パスは、親ルートを基準にした指定です。

```tsx
<Route path="/app" element={<Layout />}>
  <Route path="notes/:id" element={<NoteDetail />} />
</Route>
```

子ルートを相対パスにすると、自分が属する親との関係だけを記述できるため、親のパスを重複して書かずに済みます。

ネストした子ルートに絶対パスを使う場合は、親のパス全体から始めるという制約があります。そのため、親子構造を持つルートでは、相対パスを使うと関係が読み取りやすくなります。

### Dynamic Segmentで変化するURLを扱う

Dynamic Segmentは、URLの中で変化する部分です。次のコードでは、`:id`がその部分に当たります。

```tsx
<Route path="notes/:id" element={<NoteDetail />} />
```

個々のデータごとにルートを作る代わりに、共通のパターンでURLを受け付けます。画面側では、URLから得た値を使って表示対象を切り替えられます。画面の構造と、表示するデータを分けて考えるための仕組みです。

### ルートは、定義順よりも条件の具体性で選ばれる

```tsx
<Route path="notes/:id" element={<NoteDetail />} />
<Route path="notes/new" element={<NewNote />} />
```

React Router v6では、複数のルートが同じURLに一致するとき、より具体的な条件が優先されます。

固定文字を指定したルートは、変化する値を受け付けるルートよりも具体的です。そのため、`/notes/new`にアクセスした場合は、`notes/new`が優先されます。

このようなルートの優先順位を定義順で調整する必要はなく、`/`を最後に置く必要もありません。定義は、画面の役割や親子関係が読み取りやすい順序で整理できます。

## バックエンドとの通信

### リクエストのヘッダーとボディ

フロントエンドからバックエンドへ送るHTTPリクエストでは、ヘッダーとボディが異なる役割を持ちます。

- **ヘッダー**：認証情報やデータ形式など、リクエストに付随する情報を伝えます。
- **ボディ**：登録内容や更新内容など、処理の対象となるデータを伝えます。

すべてのリクエストにボディがあるわけではありません。また、URLのパスやクエリパラメーターを使って情報を渡すこともあります。

### Content-Type

`Content-Type`は、ボディに含まれるデータの形式を相手に伝えるヘッダーです。例えば、`application/json`は、ボディがJSON形式であることを示します。

形式を宣言するための情報なので、`Content-Type`を指定するだけでデータそのものが変換されるわけではありません。

## Viteの環境変数

環境変数は、APIの接続先など、実行環境によって変わる設定をコードから分離するために使います。

Viteでは、標準設定でフロントエンドのコードから参照する環境変数に`VITE_`という接頭辞を付けます。例えば、`VITE_API_URL`は`import.meta.env.VITE_API_URL`として参照できます。

`VITE_`付きの環境変数はブラウザー側のコードに公開されるため、秘密のAPIキーやパスワードの保存には使いません。
