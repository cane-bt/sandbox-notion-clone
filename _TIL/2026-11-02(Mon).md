## 講座22: token の保存（AI による整理）

- 登録・ログイン API が返す token を localStorage.setItem("token", token) で保存する。
- フォームは保存後に共有ユーザーを更新し、送信中のボタン無効化と失敗アラートを扱う。
- 保存だけでは API に token は送られない。localStorage は JavaScript から読み取れるため、HttpOnly Cookie と同じ保護ではない。

## 講座23: token 付きユーザー取得（AI による整理）

- request interceptor は送信前の共通処理。関数をフォルダーに置くだけでは動かず、api.interceptors.request.use(addAuthorizationHeader) で登録する。
- config は Axios がまとめた通信設定。url・method・baseURL・data・headers などを持つ。InternalAxiosRequestConfig は headers が必須の型。
- 共通設定の Content-Type と Axios 標準の Accept に、token があれば Authorization: Bearer を追加する。token がなくても通信は継続する。
- Bearer はトークン提示の方式。ユーザー用に限らずサービス用のアクセストークンなどにも使われ、JWT と同義ではない。
- /auth/me はアプリ側の API パスであり、Axios が用意するユーザー取得機能ではない。本リポジトリには受け側の実装がなく、別バックエンドの仕様確認が必要。

## 講座24: 起動時復元と useEffect（AI による整理）

- useEffect の行では関数を React に渡し、中身は DOM への反映後に実行される。コード上の位置で通信が即時実行されるわけではない。
- 最初は useState(true) により isLoading が true なので、読み込み中の JSX を return する。その回の App の実行は終了する。
- 通信完了後の setIsLoading(false) が再描画を要求する。App が最初から再実行され、今度は false なので通常画面の JSX を返す。return の位置で処理を待って再開するわけではない。
- useState の初期値は通常の再描画で状態を true に戻すものではない。finally で false にするため、成功と失敗のどちらでも読み込みは終わる。
- 依存配列は Effect が使う値から決める。取得関数を Effect 内へ移し、setCurrentUser を依存に含める。cleanup 後は古い結果を無視する。通信のキャンセルとは別。
- StrictMode の開発時は追加の Effect 実行がある。[] はアプリの生涯で絶対に1回だけという保証ではない。
- Hook は条件分岐・早期 return より前で毎回同じ順序で呼ぶ。const を必ずファイル上部に集めるという規則はない。
- React Compiler が主に自動化するのは useMemo・useCallback・memo 相当のメモ化。useEffect や cleanup を不要にするものではない。現リポジトリには Compiler の明示的な導入設定なし。
- Effect に直接通信を書く基本形を学んだ後、カスタム Hook や取得ライブラリで整理できる。長い Effect を毎回書くこと自体が理想ではない。
