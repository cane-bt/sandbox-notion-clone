## 確認したこと・理解の整理

### 1行と子一覧の役割

**対象ファイル・箇所**

[src/components/NoteList/index.tsx](../src/components/NoteList/index.tsx) の `NoteList`（質問時点の43行目・50行目）と、[src/components/NoteList/NoteItem.tsx](../src/components/NoteList/NoteItem.tsx) の `NoteItem`。

**確認の出発点**

43行目と50行目の各コンポーネントの違いが分からなかった。続いて、親の `NoteItem` と子の `NoteList` が両方ある場合の `return` の中身を確認した。

**AI による補足**

`NoteItem` はノート1件のタイトル・アイコン・追加ボタンなどを表示する。`NoteList` は指定した親を持つノートを並べる。`NoteList` の中で自分自身を使うことで、子・孫へ同じ処理を繰り返す。これが再帰である。

実装では、絞り込んだノートごとに次の2要素を同じ `div` 内へ置く。どちらかを選ぶ条件分岐ではない。

```tsx
<NoteItem
  key={note.id}
  layer={layer}
  note={note}
  onCreate={(e) => createChild(e, note.id)}
  onExpand={(e) => fetchChildren(e, note)}
/>
<NoteList layer={layer + 1} parentId={note.id} />
```

「旅行」の処理中なら、前者は旅行の1行、後者は旅行の子である京都・大阪の一覧を担当する。京都にも同じ組み合わせが作られるため、京都の子である持ち物も表示できる。

```text
最上位の NoteList
└─ div
   ├─ NoteItem：旅行
   └─ NoteList：旅行の子一覧
      ├─ div
      │  ├─ NoteItem：京都
      │  └─ NoteList：京都の子一覧 → 持ち物
      └─ div
         ├─ NoteItem：大阪
         └─ NoteList：大阪の子一覧 → 該当なし
```

これはコンポーネントの関係を示す説明図であり、完成した DOM そのものではない。`NoteItem` も自身の `return` にある要素を返す。Fragment の `<>...</>` は DOM の囲み要素を追加しない。

`layer + 1` は子の階層を1つ深くする。`NoteItem` は `layer * 12 + 12` で求めた値をpx単位の `paddingLeft` にする式で左余白を設定しており、`layer` が0、1、2なら12、24、36pxになる。

### 子がない場合

**対象ファイル・箇所**

[src/components/NoteList/index.tsx](../src/components/NoteList/index.tsx) の `NoteList` の `return`・`filter`・`map`。

**確認の出発点**

親の `NoteItem` が存在し、子の `NoteList` が存在しない場合の `return` を確認したかった。

**AI による補足**

厳密には、子ノートがなくても親側には `<NoteList layer={layer + 1} parentId={note.id} />` が含まれる。その子の `NoteList` 内で条件に合うノートが見つからず、`filter` の結果が `[]` になる。

空配列への `map` はコールバックを一度も実行せず、結果も `[]` になる。子側の戻り値は、内容として次と同じ状態になる。

```tsx
<>{[]}</>
```

これによって子側には何も表示されず、親の1行だけが残る。空の結果から新たな `NoteList` は作られないので、循環のない親子データでは子がない枝で再帰が止まる。

### 階層ごとの値の追跡

**対象ファイル・箇所**

[src/components/NoteList/index.tsx](../src/components/NoteList/index.tsx) の `NoteList` の引数、`filter`（質問時点の40行目）、再帰部分（同50行目）。共有配列は [src/modules/notes/notes.state.ts](../src/modules/notes/notes.state.ts) の `useNoteStore`・`getAll` から取得する。

**確認の出発点**

`notes.filter((note) => note.parentId == parentId)` に、旅行の例で1回目・2回目以降はどのように値が入るのか想像できなかった。

**AI による補足**

左の `note.parentId` は、`filter` がいま調べている1件の親ID。右の `parentId` は、その `NoteList` が Props として受け取った親IDである。

以下は説明用のデータであり、実際の保存データではない。学習に必要なプロパティだけを示す。全件が共有 state に入っていると仮定する。

```ts
const notes = [
  { id: 1, title: '旅行', parentId: undefined },
  { id: 2, title: '京都', parentId: 1 },
  { id: 3, title: '大阪', parentId: 1 },
  { id: 4, title: '持ち物', parentId: 2 },
];
```

最初は `<NoteList />` として `parentId` を省略する例で考える。右辺は `undefined` なので、配列全体を次のように比較する。

| 調べるノート | 比較 | 残るか |
| --- | --- | --- |
| 旅行 | `undefined == undefined` | 残る |
| 京都 | `1 == undefined` | 残らない |
| 大阪 | `1 == undefined` | 残らない |
| 持ち物 | `2 == undefined` | 残らない |

残った旅行について `map` が要素を作る。旅行の `id` は `1` なので、子には `<NoteList parentId={1} layer={1} />` が渡される。今度は右辺が `1` になる。

| 調べるノート | 比較 | 残るか |
| --- | --- | --- |
| 旅行 | `undefined == 1` | 残らない |
| 京都 | `1 == 1` | 残る |
| 大阪 | `1 == 1` | 残る |
| 持ち物 | `2 == 1` | 残らない |

各階層の比較をまとめると次のようになる。

| 担当する一覧 | 受け取る `parentId` | `filter` の結果 | 次に作る子の `NoteList` の `parentId` |
| --- | --- | --- | --- |
| 最上位 | `undefined` | 旅行 | `1` |
| 旅行の子 | `1` | 京都、大阪 | `2` と `3` |
| 京都の子 | `2` | 持ち物 | `4` |
| 持ち物の子 | `4` | `[]` | なし |
| 大阪の子 | `3` | `[]` | なし |

毎回、同じ共有 state の `notes` 全体を対象に絞り込む。前回の絞り込み結果を次の `NoteList` に渡すわけではない。また、1つの `parentId` を順番に書き換えるわけでもない。それぞれの `NoteList` が自分の `parentId` を持つ。この表は階層の関係を説明するもので、React の実行回数や再描画順序を保証するものではない。

整理時の追加補足として、実装は `===` ではなく `==` を使用している。`null == undefined` も `true` になるので、実データの親IDが `null` でも最上位の絞り込みに一致する。上の例では説明を絞るため `undefined` を使っている。

### 配列の順序と表示順

**対象ファイル・箇所**

[src/components/NoteList/index.tsx](../src/components/NoteList/index.tsx) の `filter`・`map`。整理時の補足対象は [src/modules/notes/notes.state.ts](../src/modules/notes/notes.state.ts) の `set`・`getAll`。

**確認の出発点**

仮に `notes` が逆順に sort されていても同様の表示になるか確認した。

**AI による補足**

`notes` が「持ち物、大阪、京都、旅行」の順なら、最上位の絞り込みでも最後の旅行を見つけられる。`filter` は配列全体を調べ、条件に合う要素の相対順序を保つ。旅行の子を探す結果は「大阪、京都」となり、その順に `map` で表示される。

```text
元の順序       逆順
旅行           旅行
  京都           大阪
    持ち物       京都
  大阪             持ち物
```

親子関係は `id` と `parentId`、兄弟同士の表示順は `NoteList` が受け取った `notes` の並び順で決まる。子が親より先に配列へ入っていても、両方のデータが揃っていれば親子関係は変わらない。

整理時にコードを確認して追加した補足：現在の store の `set` はIDをキーにしたオブジェクトへまとめてから `Object.values(uniqueNotes)` を返す。通常の非負の整数IDではキーが数値順に列挙されるため、APIや `set` への入力を逆順にしただけで、`getAll()` が逆順を返すとは限らない。会話の回答は「描画時の `notes` 自体が逆順」という仮定についての説明である。
