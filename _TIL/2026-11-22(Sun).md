## 確認したこと・理解の整理

### 例外をどこで受け取るか

**対象ファイル・箇所**　[src/modules/notes/note.repository.ts](../src/modules/notes/note.repository.ts) の `update`、[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `saveTitle`

**確認の出発点**　なぜ戻り値の型エラーが出るのか。`throw error;` は呼び出し先と呼び出し元の両方に必要か。

**AI による補足**

質問時点では、成功すると `Note` を返す一方、通信に失敗すると `catch` で通知したあと関数の末尾に到達していた。その場合は Promise が `undefined` で正常終了するため、宣言した `Promise<Note>` と食い違う（TS2366）。

`throw error;` は、捕まえたエラーを呼び出し元へ伝える書き方。たとえば repository でログだけを記録し、失敗時の表示は画面に任せるなら、記録後に再び投げる。現在の `update` は通信エラーが起きるとそのまま呼び出し元に伝わる。画面では `await` から `catch` に移り、成功時の `noteStore.set([updatedNote])` は実行されない。画面で失敗への対応が完了すれば、再度投げる必要はない。

### ストアの戻り値と依存配列

**対象ファイル・箇所**　[src/modules/notes/notes.state.ts](../src/modules/notes/notes.state.ts) の `useNoteStore`、[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `NoteDetailContent`

**確認の出発点**　なぜ `useNoteStore.set` はエラーになるのか。`const noteStore = useNoteStore();` を使うなら、依存配列はどう書くか。

**AI による補足**

TS2339 が出たのは、Hook 自体に `set` がないため。`getOne` と `set` は Hook が返すオブジェクトにある。取得は `noteStore.getOne(id)`、保存成功後は `noteStore.set([updatedNote])` と書ける。ストアが `Note[]` を受け取るので、更新が1件でも配列で渡す。

Hook はレンダーごとにオブジェクトを作る。依存配列に `noteStore` を入れると、取得結果によるストア更新でも取得処理が再び走り得る。`const setNotes = noteStore.set;` は既存の関数に別名を付けるだけで、関数の参照は Hook 内の `useCallback` で安定している。Effect 内では `setNotes([result])` を使い、依存配列を `[id, setNotes]` とする。

### タイトル編集と保存失敗

**対象ファイル・箇所**　[src/components/TitleInput.tsx](../src/components/TitleInput.tsx) の `TitleInput`、[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `saveTitle`

**確認の出発点**　未コミットのタイトル編集に、さらに改善できる点はあるか。

**AI による補足**

レビュー時は `readOnly` が入力を妨げていた。また、入力ごとに PATCH すると、後から届いた古い応答がストアのタイトルを上書きし得る。現在は `onChange` で下書きを更新し、フォーカスが外れた時点で値が変わっていれば送信する。保存中は入力を無効にし、失敗時は入力欄のそばにエラーと再試行ボタンを表示する。読み込み失敗と状態を分けることで、保存失敗後も下書きが残る。

### 保存開始と成功のタイミング

**対象ファイル・箇所**　[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `saveTitle`

**確認の出発点**　質問時点の35〜36行目は、39行目のストア更新後に置く方がよいか。

**AI による補足**

`setIsSaving(true)` は保存が必要と判定した直後に呼ぶ。成功後に移すと、応答を待つ間も入力できてしまい、成功直後には `finally` が保存中の表示を解除する。

`setSaveFailed(false)` は前回のエラー表示を消す処理。現在は再試行の開始時に消し、再び失敗すれば `catch` で表示する。成功するまでエラーを残す仕様なら、この行だけ成功後に置く選択もある。

### 入力欄に渡す初期値

**対象ファイル・箇所**　[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `NoteDetailContent`、[src/components/TitleInput.tsx](../src/components/TitleInput.tsx) の `TitleInput`

**確認の出発点**　質問時点の81行目で、入力欄に渡す値はどう変わったか。

**AI による補足**

以前は `initialData={note}` でノート全体を渡していた。現在は `initialTitle={note.title ?? ''}` と書き、タイトルが `null` または `undefined` のときは空文字を渡す。「無題」は空欄に表示する `placeholder` なので、実際の下書きに「無題」という文字列は入らない。

## 残っている確認事項

実装時のビルドと変更3ファイルの ESLint は通過。公開時にモック API を使ったブラウザ操作で、入力中は送信せず、フォーカスが外れると保存を開始することを確認した。失敗後も下書きが残り、再試行に成功するとエラー表示が消えた。実バックエンドとの接続は未確認。
