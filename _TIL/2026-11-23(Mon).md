## 確認したこと・理解の整理

### 関数を定義する丸括弧

**対象ファイル・箇所**　[src/components/Editor.tsx](../src/components/Editor.tsx) の `Editor`（質問時点の6行目）

**確認の出発点**　なぜ関数名の後ろに空の `()` が必要なのか。

**AI による補足**

`function Editor() {` の丸括弧は、呼び出し元から受け取る値に名前を付ける場所。今回は受け取る引数がゼロなので中身は空になる。JavaScript の関数宣言では、ゼロ個でも丸括弧は必要になる。

すぐ下の `useCreateBlockNote({ dictionary: ja })` にも丸括弧がある。こちらは関数の呼び出しで、日本語辞書を含む設定オブジェクトを1個渡し、戻り値を `editor` に代入している。

### スラッシュ入力で開いた翻訳メニュー

**対象ファイル・箇所**　特定ファイルなし（Chrome 拡張機能の表示）

**確認の出発点**　見出しを入力すると開くポップアップは Raycast のものか。

**AI による補足**

画面にあった「スラッシュコマンドメニュー」「翻訳結果がありません」「このサイトで無効化」の3つが、端末内の Chrome 拡張機能「Google 翻訳 - サイドパネル」の表示文言と一致した。入力欄の `/` に拡張機能が反応していた。このサイトだけで止めたい場合はポップアップ右下の「このサイトで無効化」を選べる。

### 本文だけが暗く見えた理由

**対象ファイル・箇所**　[src/components/Editor.tsx](../src/components/Editor.tsx) の `Editor`、[src/styles/variables.css](../src/styles/variables.css) の `:root`、[src/styles/reset.css](../src/styles/reset.css) のページ背景

**確認の出発点**　教材と同じコードなのに、白いページ上でエディターだけが暗いのはなぜか。

**AI による補足**

質問時のコードは教材と同じく `BlockNoteView` の `theme` を省略していた。BlockNote はこの構成でブラウザの `prefers-color-scheme` に従い、ダーク時の編集領域に `#1f1f1f` を使う。一方、ページの `--color-background` は白。親の背景色を変えるだけでエディターのテーマも切り替わるわけではない。教材撮影時の外観設定は未確認。

11月23日の整理時点では `<BlockNoteView editor={editor} theme="light" />` が実装されている。これは質問時のコードとは異なる。変更後の画面の再確認は記録されていない。

### OS の外観設定に追従する方法

**対象ファイル・箇所**　[src/styles/variables.css](../src/styles/variables.css) の `:root`、[src/components/Editor.tsx](../src/components/Editor.tsx) の `Editor`、[ADR 0033「決定」](../.claude/ADR/0033-defer-system-appearance.md#決定)

**確認の出発点**　ページ背景をユーザーの設定に合わせて変えられるか。

**AI による補足**

OS に追従するなら、CSS の `@media (prefers-color-scheme: dark)` で背景色と文字色の変数を切り替え、BlockNote 側も同じ設定に従わせる。サイドバーやタイトルは別の色変数を参照するため、それぞれの読みやすさも確認する。アプリ独自のテーマ選択を設ける場合は、選択結果をページとエディターの双方に渡す。本人は今回は教材に沿って進め、OS 追従は将来対応とすることを選んだ。

### BlockNote の開発経緯と類似ライブラリ

**対象ファイル・箇所**　特定ファイルなし（導入箇所は [src/components/Editor.tsx](../src/components/Editor.tsx) の `Editor`）

**確認の出発点**　誰がどのような経緯で開発したのか。類似ライブラリを使うと何が変わるのか。

**AI による補足**

Yousef El-Dardiry が TypeCell の開発中、入れ子、ドラッグ移動、メニューまで備えた編集部品を必要とし、2022年9月8日に BlockNote を公開紹介した。公式サイトが現在の開発チームのリーダーとして挙げているのは Matthew Lipski、Nick Perez、Yousef El-Dardiry の3人。

ProseMirror が文書構造や変更を扱い、その上の Tiptap が編集機能を拡張として組み立てやすくし、さらに BlockNote がブロック操作と UI を提供する。教材で少ないコードから見出しを選べる理由はここにある。

| 会話で比較した候補 | 今回のノート編集で何が変わるか |
| --- | --- |
| Yoopta-Editor、Editor.js、Plate | ブロックや UI を選んで構成できる。教材と同じ操作にするにはプラグインの組み合わせや保存形式の確認が必要。 |
| BlockSuite、Novel、Gutenberg | それぞれ共同編集とキャンバス、AI 入力補完、WordPress ブロックとの互換性に特色がある。用途に応じて統合や設定の範囲が広がる。 |
| Tiptap、ProseMirror、Lexical、Slate、Remirror | 文書構造や振る舞いを細かく作り込める分、見出しの選択メニューやドラッグ移動の設計を開発側が担う。 |
| Mantine Rich Text Editor、Draft.js | 前者は Tiptap に Mantine のツールバーを載せる別製品。後者は既存 React アプリの保守では候補だが、公式リポジトリはアーカイブ済み。 |
| Milkdown、MDXEditor、TOAST UI Editor | Markdown や MDX で文章を持ち出しやすい。独自ブロックを使うなら、その形式で書き戻せるか検討する。 |
| Quill、CKEditor 5、TinyMCE | それぞれ Delta 形式での変更表現、校閲、HTML 編集に強みがある。ブロック単位の操作が教材に合うかは別途確認が必要。 |
