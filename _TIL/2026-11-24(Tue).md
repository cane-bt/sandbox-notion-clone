## 確認したこと・理解の整理

### タイトルと本文の保存

**対象ファイル・箇所**　[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `NoteDetailContent` と [src/modules/notes/note.repository.ts](../src/modules/notes/note.repository.ts) の `noteRepository.update`。

**確認の出発点**　質問時点の89行目で、講座の画像にある `updateNote` を呼べなかった。既存の `saveTitle` が関係するのではないかと考えた。

**AI による補足**　`saveTitle` から共通化できるのは、変更項目を API に送り、返ってきたノートをストアへ反映する2行。11月24日の整理時点では次の関数があり、親の引数にある `id` を参照している。

```tsx
const updateNote = async (changes: { title?: string; content?: string }) => {
  const updatedNote = await noteRepository.update(id, changes);
  setNotes([updatedNote]);
};
```

`saveTitle` はタイトルが変わったときに `updateNote({ title })` を呼び、`saveContent` は本文の変更を `updateNote({ content })` で送る。タイトル固有の比較や保存中表示は `saveTitle` に残せる。

### 関数を渡す側と呼ぶ側

**対象ファイル・箇所**　[src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `NoteDetailContent` と [src/components/Editor.tsx](../src/components/Editor.tsx) の `Editor`。

**確認の出発点**　`<Editor initialContent={note.content} onChange={saveContent} />` で、なぜ `saveContent` の引数を省けるのか。

**AI による補足**　親が描画時に渡すのは関数そのもの。子の `Editor` がその関数を `onChange` という名前で受け取り、編集時に本文を渡して呼ぶ。`onChange={(content) => saveContent(content)}` と書いても同じ値が届く。

### 本文が引数に届くまで

**対象ファイル・箇所**　[src/components/Editor.tsx](../src/components/Editor.tsx) の `BlockNoteView` に渡す変更ハンドラーと [src/pages/NoteDetail.tsx](../src/pages/NoteDetail.tsx) の `saveContent`。

**確認の出発点**　`saveContent(JSON.stringify(editor.document))` で、なぜ編集した本文を `content` として受け取れるのか。

**AI による補足**　`BlockNoteView` に渡した `editor` と、変更ハンドラーが参照する `editor` は同じインスタンス。変更時にその本文を読み取る過程を分けて書くと、次のようになる。

```tsx
onChange={() => {
  const blocks = editor.document;
  const json = JSON.stringify(blocks);
  onChange(json);
}}
```

左側の `onChange=` は変更時の処理を登録する JSX の属性。内側の `onChange(json)` は親から渡された関数の呼び出しなので、ここで `saveContent(json)` が実行される。第1引数の値が仮引数 `content` に入るため、呼び出し側と名前をそろえる必要はない。`{ content }` は `{ content: content }` の省略形で、この文字列がリクエストの本文更新項目になる。
